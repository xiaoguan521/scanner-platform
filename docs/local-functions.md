# 本地功能与验证

当前支持本机 SQLite 业务、模拟执行、单台主机 TCP 端口探测及 Nuclei/Trivy/ZAP 引擎执行。`make dev` 提供网页、API、Worker、Updater，默认只监听 `127.0.0.1:8080`。引擎安装与使用见 [引擎接入](engines.md)，端口探测边界见 [端口探测](port-probe.md)；真实服务器上的运行效果仍需在获批环境验证，模拟结果单独标注。

## 操作顺序

1. 首次打开网页设置管理员（用户名 3–40 位、密码 12–72 字节，无默认密码），以后直接登录。也可用 `sec-server --init-admin admin --password-file /绝对路径/仅本人可读的文件`；默认数据库与 `make dev` 同为 `runtime/platform.db`。
2. 管理员在用户页创建用户、修改角色、启停账号。停用会撤销该用户会话；不能停用/降级自己或最后一名管理员。只读用户可看业务列表，不能修改。
3. 资产页登记主机数字 IP、业务组和负责人；镜像仓库只保存登记记录。已知 Nginx 四层转发端口可标记为“跳过”。编辑资产会重置原分类/审批记录。
4. 不清楚端口时，在任务页选择一台已登记主机，使用常用 TCP 端口预设或填写端口范围，并设置排除端口。每次最多探测 1024 个端口；资产上已标记跳过或隔离的端口自动排除。探测只建立 TCP 连接，不发送应用数据，不识别服务；运行前须确认运维授权并排除已知四层转发端口。
5. 端口探测结果显示为开放候选。回到资产页点击候选端口的“申请”按钮，再到授权页由其他运维人员审批。漏洞扫描任务只会列出已登记且已审批的 `IP:端口`；领取前再次检查审批、跳过和隔离状态，条件变化时取消任务。
6. Worker 领取模拟任务、回报一条明确标注的模拟发现项。结果带目标、业务组、负责人，可标为处理中、误报，或恢复待处理；不开放手工 FIXED。取消任务后不会插入成功结果。
7. 授权页可提交、批准/驳回范围和端口记录，不能审批自己的申请；端口探测结果不会自动获得扫描权限。
8. 创建允许的任务时可选择“定时发起”，填写首次时间及分钟间隔（0 为单次）。端口探测不支持定时重复。错过的重复任务合并为一次触发，不集中补跑。允许时间窗可跨午夜，星期指窗口开始日；窗口结束为开区间。`24:00` 可作为结束时间，开始与结束不能相同。未进入窗口的任务等待；Worker 到点本地暂停，下个窗口重新执行任务块。
9. 节点页展示真实本地心跳，停止心跳超过 10 秒会显示离线。只展示实际收到的状态，不声称围栏、TLS 或引擎已经验证。

## 规则包更新、离线导入与切换

只有 Updater 写 `vuln-data/`。Server 把上传/下载/激活操作排入 SQLite，Updater 通过本机 API 领取和回报，无数据库凭据。导入与切换分别操作，未激活的包不会改变 CURRENT。

离线 ZIP 结构：

```text
manifest.json
nuclei/...                  # 操作员提供的 Nuclei 模板
trivy/...                   # 操作员提供的 Trivy 数据；可只带一个引擎
```

manifest 必须且只包含 `version`、`engines`、`files`：

```json
{"version":"20261016.01","engines":["nuclei"],"files":{"nuclei/templates/example.yaml":"文件内容的64位SHA-256"}}
```

使用自带工具生成实际清单和哈希（不会下载或执行扫描）：

```bash
python3 scripts/package_rules.py --version 20261016.01 --nuclei-dir /路径/模板目录 --trivy-dir /路径/漏洞库目录 --output runtime/rules-20261016.01.zip
```

省略不需要的引擎参数。ZIP 最多 256 MiB、5 万文件、解压总量 8 GiB、单文件 4 GiB（兼容当前 Trivy 主库）。目录跳转、符号链接、重复文件、清单外文件、错误哈希均拒绝，已有版本内容不能覆盖。导入完成后，在版本列表点击“激活”；切回较旧版本必须使用“显式回滚”。所有操作均留审计。

在线更新使用同一种规则 ZIP：选择“从规则源下载”，提供不含凭据/查询参数的 HTTPS ZIP URL 和 ZIP 的 SHA-256，Updater 下载并导入，不跟随重定向。上游原始仓库 ZIP 没有本平台 manifest，需要先由操作员打包；目前不自动抓取 GitHub 最新版本或 OCI 数据库。真实规则源地址尚未配置，HTTPS 下载链路使用本地 TLS 测试源验证。

**当前只验证文件完整性，未做签名验证或 Nuclei/Trivy 兼容性验证。** 激活只切换本地数据版本，不启动扫描；固定引擎已通过本地夹具联调，真实服务器与完整模板库仍待验证。此边界在页面和 API 中明确返回。

## 自动检查

```bash
make build
make lint
make test               # go test -race ./...
make test-local         # 构建后启动独立临时实例，验证 9 组本地业务
```

`make test-local` 创建独立目录、数据库、规则和本机端口，不读取用户运行库、不连接任何目标。验证首次初始化/登录、用户启停、IPv4/IPv6/镜像登记、跳过端口、审批、模拟任务/取消/结果状态、定时触发、规则导入切换/失败、节点离线恢复、重启持久化和退出。结束后停止测试进程，终端打印证据目录。

附加单元测试覆盖领取并发、时间窗边界/跨午夜、到点拒绝结果与恢复、重复定时触发合并、临时修改跳过标记、旧 SQLite 表保留、ZIP 越界/篡改及 HTTPS 包哈希错误。真实服务器扫描、生产部署、PostgreSQL 实例迁移均未验证。引擎自身执行见 `make test-engines-local`。

可用 `SCANNER_PORT`、`SCANNER_DB`、`SCANNER_RULES`、`SCANNER_LOG_DIR` 调整本地端口和路径。`SCANNER_SKIP_BUILD=1 make dev` 只用于已构建的开发调试。普通启动会执行 `npm ci --ignore-scripts`、Server 模式前端构建及三个 Go 二进制构建；任一服务退出，启动脚本会停止其余进程并报告日志目录。
