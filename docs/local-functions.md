# 本地功能与验证

当前支持本机 SQLite 业务、模拟执行、单台主机 TCP 探测、自动综合扫描、自定义只读规则、Worker 本机 SSH 临时系统包采集及 Nuclei/Trivy/ZAP。`make dev` 提供网页、API、Worker、Updater，默认只监听 `127.0.0.1:8080`。引擎说明见[引擎接入](engines.md)，SSH 凭据配置见[Worker 本机 SSH 采集](ssh-collection.md)，端口范围见[端口探测](port-probe.md)；真实服务器上的运行效果仍需在获批环境验证，模拟结果单独标注。

## 操作顺序

1. 首次打开网页设置管理员（用户名 3–40 位、密码 12–72 字节，无默认密码），以后直接登录。也可用 `sec-server --init-admin admin --password-file /绝对路径/仅本人可读的文件`；默认数据库与 `make dev` 同为 `runtime/platform.db`。
2. 管理员在用户页创建用户、修改角色、启停账号。停用会撤销该用户会话；不能停用/降级自己或最后一名管理员。只读用户可看业务列表，不能修改。
3. 资产页登记主机数字 IP、业务组和负责人；镜像仓库只保存登记记录。新增/编辑表单可测试当前填写的数字 IP，不保存测试结果。Server 启动后立即检查清册中已登记主机，此后每轮完成后间隔 60 秒继续；清册每 10 秒自动刷新显示结果和检查时间，不提供手动重测。无响应可能是 ICMP 被屏蔽，不代表主机离线，也不会跳过 TCP 探测。编辑可修改 IP、业务组、负责人和端口申请，保存后重置端口审批；修改 IP 会撤销旧授权范围并清除旧可达性结果。删除有关联授权记录的资产前，先撤销并删除授权记录。已知 Nginx 四层转发端口可标记为“跳过”。
4. 不清楚端口且只需要发现开放端口时，在任务页选择“TCP 端口探测”，使用常用预设或填写端口范围（支持 `1-65535`），设置排除端口。单个端口最多等待 700ms、最多 64 个并发连接；资产上标记跳过或隔离的端口自动排除。此模式只建 TCP 连接，不识别服务或扫描漏洞。
5. 要自动做一次检查时，选择“自动综合扫描”，明确选择单台主机、获批端口范围与排除项。系统会探测范围内 TCP 端口、识别受限 HTTP(S) 响应并运行只读基线和启用的自定义规则；Worker 的 SSH profile 与端口匹配时还会临时采集系统包并执行 Trivy。全程不扩展到范围外，不扫描网段。仅 TCP 探测模式产生的开放候选仍需资产申请和运维逐端口审批；自动综合扫描只能使用本次授权范围，结果不会变成长期开通许可。
6. Worker 领取模拟任务、回报一条明确标注的模拟发现项。结果带目标、业务组、负责人，可标为处理中、误报，或恢复待处理；不开放手工 FIXED。取消任务后不会插入成功结果。
7. 授权页可提交、修改、批准/驳回、撤销和删除范围申请；修改后重新进入待审批，已批准记录先撤销再删除；不能审批自己的申请。端口探测结果不会自动获得扫描权限。
8. 任务中心可按任务 ID、目标、输入路径、状态和引擎筛选，并显示任务数、运行中、待执行和已完成计数；失败或完成的任务可按原配置新建。定时任务可修改、停用、启用、手动运行或删除，删除只停止后续调度，不删除已创建的扫描任务和结果。自动综合扫描、Trivy 和其他允许的任务可选择“定时发起”，填写首次时间及分钟间隔（0 为单次）；单纯 TCP 探测不能定时重复。错过的重复任务合并为一次触发，不集中补跑。允许时间窗可跨午夜，星期指窗口开始日；窗口结束为开区间。`24:00` 可作为结束时间，开始与结束不能相同。未进入窗口的任务等待；Worker 到点本地暂停，下个窗口重新执行任务块。
9. 节点页展示真实本地心跳，停止心跳超过 10 秒会显示离线。只展示实际收到的状态，不声称围栏、TLS 或引擎已经验证。
10. 报告页选择总览、资产或任务模板，可按业务组、资产、任务和最近发现时间筛选；点击“生成报告”后可下载 Word、8 工作表 Excel、HTML、CSV、JSON。Word/Excel 包含总览、资产和发现项，HTTP 服务与登录入口只列出实际检测到的信息；弱口令等未采集内容明确标为未采集，不生成虚假的零风险结论。报告基于当前 API 返回的数据快照，不发起扫描；没有报告历史，离开页面后可重新生成。

## 规则包更新、离线导入与切换

只有 Updater 写 `vuln-data/`。Server 把上传/下载/激活操作排入 SQLite，Updater 通过本机 API 领取和回报，无数据库凭据。导入与切换分别操作，未激活的包不会改变 CURRENT。

离线 ZIP 结构：

```text
manifest.json
manifest.json.sig            # manifest原始字节的raw64 Ed25519签名，不列入files
nuclei/...                  # 操作员提供的 Nuclei 模板
trivy/...                   # 操作员提供的 Trivy 数据；可只带一个引擎
```

manifest 必须且只包含 `version`、`engines`、`files`：

```json
{"version":"20261016.01","engines":["nuclei"],"files":{"nuclei/templates/example.yaml":"文件内容的64位SHA-256"}}
```

使用自带工具生成实际清单和哈希（不会下载或执行扫描）：

```bash
python3 scripts/package_rules.py --version 20261016.01 --nuclei-dir /路径/模板目录 --trivy-dir /路径/漏洞库目录 --signing-private-key /包外/签名私钥.pem --output /导出目录/rules-20261016.01.zip
```

省略不需要的引擎参数。工具要求已安装支持 Ed25519 的 OpenSSL，以参数切片调用并核对派生公钥类型，生成和自验原始 64 字节签名。私钥须为最多 4 KiB 的普通非符号链接文件，且位于全部引擎输入目录之外；输入目录中的私钥硬链接也会拒绝，不输出私钥或 OpenSSL 错误详情。

通过可信部署渠道将配对的 PKIX Ed25519 `PUBLIC KEY` PEM 公钥放在 `--rules-dir` 之外。Updater 下次启动时使用 `--trusted-rule-public-key /包外/受信公钥.pem`，或在本地启动脚本中设置 `SCANNER_RULE_PUBLIC_KEY_FILE=/包外/受信公钥.pem make dev`。配置是公钥文件路径；公钥最多 4 KiB、必须是普通非符号链接文件，且只有一个 PUBLIC KEY 块，无额外内容。进程启动时固定加载，不会从规则包获取信任。此配置只在下次启动生效，不会自动调整或重启当前运行实例。

网页 ZIP 最多 256 MiB；Updater 的已签名本地 ZIP/HTTPS Fetch 最多 2 GiB；均限制 5 万文件、解压总量 8 GiB、单文件 4 GiB（兼容当前 Trivy 主库）。大 ZIP 使用 `dist/sec-updater --import-bundle-file /path/to/vulnerability-data.zip`，导入后重启 Updater，再从规则版本页面激活；版本低于当前版本时必须在页面显式回滚。普通导入先验证 manifest 原始字节签名，再解析、解压和校验哈希；普通激活再次先验签再校验内容。无公钥、无签名、错误签名、目录跳转、符号链接、重复文件、清单外文件、错误哈希均拒绝，CURRENT 不变。已有版本的 manifest 和签名须完全相同，不能覆盖或给旧 unsigned 自动补签。大 ZIP 不进入 Server SQLite BLOB；HTTPS Fetch 先流式写入 Updater 私有临时文件并校验整包 SHA-256，取消或失败会清理临时文件。切换和回滚均通过规则版本页面留审计。所有操作均留审计。

在线更新使用同一种规则 ZIP：选择“从规则源下载”，提供不含凭据/查询参数的 HTTPS ZIP URL 和 ZIP 的 SHA-256，Updater 下载并导入，不跟随重定向。上游原始仓库 ZIP 没有本平台 manifest，需要先由操作员打包；目前不自动抓取 GitHub 最新版本或 OCI 数据库。真实规则源地址尚未配置，HTTPS 下载链路使用本地 TLS 测试源验证。

`SignatureVerified` 只表示当前检查实际验签成功。历史 unsigned、或没有配置公钥的只读 Inspect/List 仍可展示完整性状态，但签名状态为 false；配置公钥且存在签名时，错误签名使检查失败。Worker 的无公钥只读检查只验证文件完整性，不声称已经验证签名。未配置公钥时，普通导入、HTTPS 更新和普通激活全部拒绝。

本机 `sec-updater --prepare-engines` 准备流程只允许同一 Manager 实例刚生成的版本经 `ActivatePreparedLocal` 一次性激活，重新检查 manifest 摘要、文件哈希和防回滚。记录绑定规范根目录和版本；尝试时消费，不跨实例或重启恢复，导入/下载不产生该记录。历史 unsigned 版本不能用普通激活启用。

**完整 Nuclei/Trivy 引擎兼容矩阵、密钥轮换协议及多公钥过渡仍未实现。** 当前只有一个启动时固定加载的公钥；更换前须规划现有签名版本的兼容处理。激活只切换本地数据版本，不启动扫描；真实服务器与完整模板库仍待验证。

## 自动检查

```bash
make build
make lint
make test               # go test -race ./...
make test-local         # 构建后启动独立临时实例，验证 9 组本地业务
```

`make test-local` 创建独立目录、数据库、规则和本机端口，不读取用户运行库、不连接任何目标。验证首次初始化/登录、用户启停、IPv4/IPv6/镜像登记、跳过端口、审批、模拟任务/取消/结果状态、定时触发、规则导入切换/失败、节点离线恢复、重启持久化和退出。结束后停止测试进程，终端打印证据目录。

附加单元测试覆盖领取并发、时间窗边界/跨午夜、到点拒绝结果与恢复、重复定时触发合并、临时修改跳过标记、旧 SQLite 表保留、ZIP 越界/篡改及 HTTPS 包哈希错误。规则单测在临时目录生成测试 Ed25519 密钥，覆盖公钥文件限制、签名错误与原始字节变化、激活前篡改和本机准备能力边界；本地业务脚本也临时生成并签署夹具。真实服务器扫描、生产部署、PostgreSQL 实例迁移均未验证。引擎自身执行见 `make test-engines-local`。

可用 `SCANNER_PORT`、`SCANNER_DB`、`SCANNER_RULES`、`SCANNER_LOG_DIR` 调整本地端口和路径。`SCANNER_SKIP_BUILD=1 make dev` 只用于已构建的开发调试。普通启动会执行 `npm ci --ignore-scripts`、Server 模式前端构建及三个 Go 二进制构建；任一服务退出，启动脚本会停止其余进程并报告日志目录。
