# 目标内端口发现与服务识别

在“扫描任务”选择已登记的数字 IP。自动扫描按端口策略发现开放服务,继续执行受限服务识别和只读检查,结果写入资产画像与服务列表。独立“TCP 端口探测”只记录可连接端口,不发送应用数据、不识别版本、不产生漏洞。当前不接受域名、CIDR 或自动扩展其他主机;Worker 不解析域名。

端口策略可选常见、自定义、已登记或全端口。常见清单由管理员在系统策略中维护,覆盖常见 Linux、数据库与中间件端口;自定义支持 `22,80,8000-8100`。全端口覆盖 TCP 1–65535,须确认预计耗时与目标影响,并写入审计。排除支持同样语法,如 `3306,9000-9100`。即使自定义恰好覆盖全端口,也需要确认。

系统默认、资产和任务排除取并集,再加入 `EXCLUDED_PROXY` 与有效隔离端口。排除端口在 TCP 连接、协议识别、Web 检查和漏洞检测各阶段都不能连接。创建与领取任务时复核;任务详情和报告保留本次实际排除范围。开放端口不需要逐项再审批;旧申请流程保留为台账。

| 强度 | 并发连接 | 每秒连接 | 连接超时 |
|---|---:|---:|---:|
| 温和 | 8 | 20 | 1500 ms |
| 标准 | 32 | 100 | 1000 ms |
| 积极 | 64 | 250 | 700 ms |

默认标准,全端口默认温和。协议识别有每端口预算(最高 3 次)与总预算,结果不保证能识别所有产品。已知 Nginx stream 等四层转发端口应排除;仅建立 TCP 连接也可能触发代理上游连接。疑似转发特征会持久化隔离,本任务停止进一步检查,后续任务直接跳过,由管理员填写复核原因后解除。无响应超时等异常按阈值隔离;未知服务不会仅因未识别就判为代理。HTTP 预检、代理和原生配置检查共享每个端点 160 次请求的上下文预算及强度限速;TLS 隧道模板另由每模板一次 GET 白名单和引擎速率约束。

资产登记或人工重测只向该数字 IP 发送一次 ICMP echo,超时 2.5 秒。未响应表示未知,不能判定离线,不会阻止 TCP 检测。登录入口只做识别,不尝试登录、默认口令或爆破。

本机离线验证: `go test -race ./internal/portprobe ./internal/executor ./internal/repo`。使用测试假拨号器与回环 HTTP 服务,不连接真实业务目标。排除端口的真实数据包验证需在隔离靶机环境单独完成。
