# 单台主机 TCP 端口探测

任务中心提供“TCP 端口探测”，用于在不知道服务端口时，对一台已经登记的主机做有限连接检查。运行人必须确认运维授权，并在已知 Nginx stream 等四层转发端口时将其加入排除项。

探测只针对资产登记中的一个数字 IP，不接受域名、CIDR、IP 列表或网段；只使用 TCP，不发送 HTTP、TLS 或其他应用数据，不读取横幅，不识别服务版本，也不运行漏洞模板。每个端口最多等待 700 毫秒，同时最多连接 4 个端口。每次任务在应用排除项前最多选取 1024 个不同端口；全端口范围会被拒绝。

“常用端口”预设的固定清单为：

```text
22, 80, 443, 1521, 2181, 2888, 3000, 3306, 3888, 5000,
5236, 5258, 5432, 5672, 6379, 7001, 8000, 8001, 8080, 8081,
8088, 8443, 8848, 9000, 9090, 9092, 9443, 15672, 9848, 9849,
54321
```

也可选“仅自定义范围”或“常用端口 + 自定义范围”。范围为闭区间，使用英文逗号分隔，例如 `8000-8100, 9000`。排除项使用相同格式，例如 `443, 8000-8010`。服务端会重新解析和限制范围，不能依靠浏览器校验绕过 1024 端口上限。

资产中 `EXCLUDED_PROXY` 和处于 `ACTIVE` 状态的隔离端口会自动加入排除项。TCP 连接会到达目标监听端口；如果该端口是 Nginx stream 转发，连接可能进一步触发上游连接。因此不确定转发配置时，应先请运维确认，不能把“只连接、不发送数据”理解为不会触达上游。

任务只保存成功建立 TCP 连接的端口作为开放候选；不生成漏洞发现项。候选端口在资产页点击“申请”后进入端口申请列表，由其他运维人员审批。Nuclei、ZAP 等网络漏洞扫描只列出已登记且已审批的端口，并在 Worker 领取任务时再次检查审批、跳过和隔离状态。端口探测任务不支持定时重复。

本地运行可使用 `make dev`，打开“扫描任务中心”创建“TCP 端口探测（单台主机）”任务。单元测试通过注入本地假拨号器验证范围选择、排除和回报流程，不连接公司服务器。
