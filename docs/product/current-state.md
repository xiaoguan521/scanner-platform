## 当前边界和优先缺口

安全扫描仍只处理用户明确指定且已登记/审批的目标；TCP 端口探测限定单台已登记主机，ICMP 只向已登记主机发送一次有界 echo。端口探测开放结果不会直接授权漏洞扫描。

如果继续按产品旅程推进，建议补真实浏览器回归，再补独立通知中心和系统设置。授权范围页已按服务端 `expiryState` 提供七天内到期/已过期提醒和筛选；审计查询、任务详情/日志、暂停/恢复和计划运行历史已经提供安全只读投影；资产 CSV 预览/确认已经完成；报告页已经保留服务端历史和异步作业状态，刷新或离开页面后仍可查看已有作业。

## 2026-10-21：总览风险评分、趋势与下钻

总览页现在按 [风险评分口径](./risk-score.md) 计算 0–100 风险评分、有风险资产数和严重度分布，并提供 7、30、90 天活动系统/Web 漏洞趋势。风险业务组和风险资产表按活动发现项计算，业务组、资产、严重度和检测口径等数字可直接进入 `/findings` 对应筛选；业务组和资产筛选保存于 URL，可刷新、前进/后退并从标签移除。

这些指标在 Server 模式由 `GET /api/v1/dashboard/summary?days=7|30|90` 聚合返回，任务清册仍独立轮询；演示模式继续用 fixture 计算。趋势按每日 UTC 结束时仍活动的系统/Web 漏洞数计算，接受风险按 25% 权重计入，FIXED/FALSE_POSITIVE 不计入风险评分；无真实发现项时展示空状态而不是伪造结果。待处置卡片只纳入 `OPEN`、`REOPENED`、`IN_PROGRESS` 的严重/高危系统或 Web 漏洞，最多展示 5 条并显示总数；已接受风险、误报和已修复项不进入待处置卡片。聚合响应不包含证据、凭据、原始请求/响应或引擎输出。纯函数和 API race 测试覆盖权重、封顶、资产去重、趋势、业务组/资产排序、待处置筛选、认证和非法趋势窗口；真实浏览器点击下钻和大数据量性能仍待独立验收。

## 2026-10-21：总览首次使用清单与待处置卡片

Server 模式下，当资产、非模拟扫描任务或已完成扫描结果尚未形成闭环时，总览显示“快速开始”清单：登记第一个资产、发起第一次扫描、查看第一份结果。每项都有明确跳转，完成项自动打勾；三项完成后清单隐藏。演示模式不把预置数据误判为新用户，也不显示这张清单。

总览新增“待处置严重/高危漏洞”卡片，读取当前已认证列表中的系统/Web 漏洞，只显示 `OPEN`、`REOPENED`、`IN_PROGRESS`，按严重度和最近发现时间排序，最多列出 5 条；数量徽标显示完整待处置数量，卡片和每行均可跳转到漏洞筛选。卡片仅呈现标题、目标和状态，不新增扫描请求或扩大目标范围。

演示脚本（隔离本地 Server）：清空临时 SQLite 后登录，打开“总览”确认清单出现；点击“去登记”完成一条文档保留地址资产，再返回总览确认第一项打勾；点击“去扫描”创建一个明确授权的任务，完成后确认第二项打勾；任务完成后进入漏洞列表并返回总览，确认第三项打勾且清单隐藏。准备包含严重/高危活动漏洞的合成数据时，确认卡片显示总数、最多 5 条记录和筛选跳转。演示不连接外部目标。

## 自动综合扫描立即任务向导（2026-10-20）

`/tasks` 的自动综合扫描立即任务使用四步向导：选择一台已登记数字 IP 主机，填写现有端口策略、强度、任务排除和自定义规则，设置执行时间窗，再核对目标、有效端口预览、系统/资产/任务排除、隔离端口和时间窗后勾选运维授权。前后返回保留配置；修改配置后需要重新勾选授权。下一步只校验当前步骤，未授权或未到确认步骤不会创建任务。全端口（含自定义范围覆盖全端口）保留提交时的再次确认。

端口预览仅根据当前资产和系统策略计算，Server 继续通过原 `POST /api/v1/tasks` 重新校验和冻结目标与端口；系统策略读取失败或有效端口为空时不能从方案步骤继续。选择定时发起、模拟任务或离线输入扫描仍进入原表单，旧任务复制可继续使用。该步骤没有新增扫描方案 API 或调整 Worker 执行能力。

前端回归：在仓库根目录运行 `node web/src/pages/Tasks/policy.test.mjs`、`node web/src/pages/Tasks/wizard.test.mjs` 和 `npm --prefix web run build`。手工演示时先尝试空目标“下一步”，再选择文档保留地址段中的已登记实验资产，设置自定义范围和排除，前后返回检查值保留，确认页检查有效端口和时间窗；未勾授权应无法创建。全端口确认选择“返回修改”时不应发起创建请求。以上演示仅针对隔离实验环境。

自动综合扫描方案步骤提供“快速检测”和“标准检测”两张预置方案卡片。快速检测使用常见端口和温和强度，适合首次确认暴露面；标准检测使用常见端口加可选自定义范围和标准强度，适合日常例检。卡片只写入现有产品级端口策略、强度、排除项和规则选择，Server 仍会重新校验资产、授权、时间窗和实际端口；不把引擎命令行暴露给用户。用户可以在选择预置方案后继续调整字段，确认页显示当前方案名称和最终参数。

## 定时计划历史运行（2026-10-21）

定时计划每次由 Server 触发时写入独立的 `schedule_runs` 记录，并通过 `GET /api/v1/schedules/{id}/runs` 按时间倒序分页查询。历史只包含触发时间、任务状态、任务 ID 和安全错误摘要；任务状态从当前任务记录实时映射，任务被彻底删除后显示为“任务记录已删除”。删除计划不会删除历史，单次计划和重复计划均记录每次实际触发，错过的重复运行仍按原策略合并，不补跑。

任务中心的定时计划表提供“历史运行”入口。演示模式明确提示不读取服务端历史；真实模式只读取当前用户可见的安全投影，不传递目标、输入路径、凭据或引擎输出。仓储/API 测试覆盖成功触发、状态映射、分页、删除计划后保留历史和无效触发失败记录；PostgreSQL 运行时和真实浏览器交互仍待验收。

## 2026-10-20：资产 CSV 导入最小闭环

资产页提供下载模板、选择 CSV、逐行预览、明确勾选后整批确认及刷新台账。仅管理员和安全工程师可导入；演示模式禁用导入入口。固定表头 `kind,address,businessGroup,owner`，可加最后一列 `name`；UTF-8 无 BOM，最多 1 MiB / 1000 条数据记录。支持数字 IP 主机和现有镜像仓库格式，禁止导入端口或审批字段。非法行、文件内重复及现有资产重复均显示原因，任何错误都阻止整批确认。

预览只读资产并在 Server SQLite 的 `asset_import_previews` 暂存规范化行，不登记资产、不调用 DNS/Ping/扫描。预览绑定当前用户，有效 15 分钟；新预览替换该用户旧预览。确认仅接收服务端预览 ID，重新检查唯一约束，以同一事务写资产/profile、消费预览和计数审计；重复确认、过期、跨用户及并发资产冲突均拒绝，冲突整批回滚。成功后清空暂存行；过期行在下次预览时清理。后台既有清册可达性轮询会在确认入库后按原策略处理新增主机，导入请求本身不探测目标。

尚未提供导入历史查询、更新/覆盖已存在资产、端口导入或 PostgreSQL 写入实现。CSV 导出只返回当前清册的稳定台账字段，不包含服务详情和登录入口。

## 2026-10-20：漏洞分类筛选 URL 状态

`/findings` 将严重度、生命周期状态、检测方式、置信度、风险类型和“仅已验证”保存到 HashRouter 路由的查询参数：`severity`、`status`、`method`、`confidence`、`risk`、`onlyVerified`。筛选组合保留原有交集语义；刷新和浏览器前进/后退均从当前 URL 恢复。选择筛选使用 replace 更新，不逐次增加历史记录。默认值省略，非法枚举、重复的筛选键和非法布尔值恢复默认并规范化；其他功能的查询参数保留。

目标/组件/CVE 自由文本仍只存在页面内存，刷新不恢复；URL 中既有的 `q` 也会移除，避免页面继续传播带资产地址的查询链接。该处理不能清除进入页面前已存在的历史记录。不改变 Server API、发现项数据、扫描目标或授权范围。

## 2026-10-20：发现项详情抽屉

## 单项接受风险与状态事件（2026-10-20）

漏洞抽屉支持单项接受风险：仅 OPEN、REOPENED、IN_PROGRESS 可接受，需填写 1–500 UTF-8 字节且无控制字符的原因，以及未来 365 天内的带时区到期时间。ACCEPTED_RISK 可撤销回 OPEN；FIXED 和 FALSE_POSITIVE 不能接受风险，手动状态更新不能进入或离开 FIXED，也不能重复设置同一状态。演示模式仅提示，不保存操作。

Server 每分钟 Tick 检查到期，发现项列表、状态更新和扫描回报前也补查。到期及历史无期限接受风险安全恢复 OPEN，并清除活动接受字段；扫描结果不能覆盖接受原因/期限。完整扫描自动 FIXED、重检 REOPENED、手工更新和到期重开均在 SQLite finding_events 保留状态事件，抽屉显示纯文本时间线。事件、发现项 JSON 和审计在同一事务更新，审计只链接事件 ID 与状态，不复制原因。当前实现仍是本地 SQLite，未接入 PostgreSQL 运行时；架构要求的到期通知渠道尚未实现，当前以状态事件和时间线供复审；指派/备注见下节；批量状态处置和单项复测见后节。


## 单项漏洞指派与追加备注（2026-10-20）

详情抽屉支持指派或清除漏洞处置人，并追加不可修改的纯文本备注。处置人独立于资产负责人 Owner，仅可选当前启用的管理员/安全工程师；账户被停用后已有指派作为历史快照保留，新指派会拒绝。备注限制为 1–2000 UTF-8 字节、非空白且不含控制字符及 Unicode 行/段落分隔符（U+2028/U+2029），按作者快照和时间展示；演示模式提示而不保存。

Server 在同一 SQLite 事务中校验执行者/被指派者并写入发现项、指派历史或备注及审计。审计不复制备注正文，只记录备注 ID 和字节数。引擎重复扫描保留人工指派；追加备注不改变漏洞状态、指纹或资产负责人。所有新读取需要认证，候选列表仅管理员/安全工程师可读；写入仅管理员/安全工程师且需要现有 CSRF 请求头；无认证配置时新端点关闭。单项复测见后节；通知、指派历史查询 UI、备注分页或 PostgreSQL 运行时实现仍待补充；真实浏览器交互仍待验收。

## 批量漏洞状态处置（2026-10-20）

漏洞表格提供显式行选择、跨分页/筛选保留选择及原状态快照，最多 100 项。工具栏选择修复中、误报、接受风险或恢复待处理，经包含 ID/原状态的确认框保存；接受风险统一填写原因和期限。状态变化后会阻止旧选择继续提交；服务端也校验 expectedStatus。失败保留选择，成功用返回记录替换并清空；演示模式仅提示。

Server 共享单项校验，在一个 SQLite 事务内固定顺序预读、CAS 更新、逐项状态事件和审计；不存在、状态变化、非法流转或任一写入失败均整批回滚。保留人工指派、备注和稳定指纹，不改变扫描状态。到期仍由既有 Tick/列表/单项补查处理，失败批次不额外触发事务外到期写入。单项复测在同一 SQLite 事务中复用已完成父任务冻结输入，独立 HTTP 任务缩小到发现项目标，自动综合任务恢复父任务精确端口集合；复测关系和状态可查询，活动复测重复提交冲突。批量指派、到期通知、真实浏览器和 PostgreSQL 运行时验收仍待补充。
