## 本轮推进边界

本轮已完成 P0 的信息架构基础、真实数据通道收敛和主要页面的语义组件抽取，并补上系统管理闭环：一级导航固定为“总览、资产、扫描、漏洞、报告、系统”六个域，管理员可维护时区和新登录会话时长，所有登录用户可查看授权/风险/任务提醒并标记已读；服务端持久化、权限和审计保持在 Server。状态文案和颜色由共享组件维护，页面只负责业务组合。

五条核心旅程的 PostgreSQL 浏览器验收已经完成，节点生命周期首阶段和节点清册管理闭环也已落地：注册/吊销由管理员显式操作，心跳刷新在线状态，离线与恢复事件进入审计/通知，清册可查看状态/事件，管理员可为已登记节点签发一次性令牌，两个后端保持同一语义；独立 TLS 节点监听、客户端 CA/mTLS 及证书/令牌 SIGHUP 轮换已实现，离线材料工具还支持本地目录级证书轮换；Linux Worker 可信启动器已能创建专属 network namespace 并传递父 namespace fd。后续处理远程 supervisor 编排、自动证书签发、其他消息渠道、审计高级筛选、真实服务器/国产系统覆盖和发布级范围抓包等剩余领域闭环。SQLite 仍是默认便携模式，PostgreSQL 必须显式选择，未实现的接口不会回退到 SQLite。

## 交付约束

- 真实扫描仍只接受已登记且明确授权的数字 IP 和端口；路线图不扩大扫描范围。
- 真实测试只使用隔离靶机和明确授权的目标；不能把本地扫描结果或密钥写入仓库。
- 每个工作包完成时同步 `docs/product/current-state.md`、`docs/verification-log.md` 和相应 OpenAPI 契约。

## 本次推进：部署门禁与审计定位

已增加 `make verify-deploy`。它先由 Docker Compose 将候选文件规范化为
JSON，再检查服务角色、显式网络、host namespace、特权和 capabilities、
digest 固定镜像、secret 文件引用、端口发布边界，以及 Worker 的规则目录只读和 runtime 可写
约束。该门禁不替代 Linux 围栏、抓包和真实部署验收，也不意味着生产
Compose 已经交付。系统审计清册同时支持按对象 ID 精确定位，SQLite、
PostgreSQL、API 和前端筛选保持相同语义。
