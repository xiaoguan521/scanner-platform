# 产品开发路线图

本文把产品化调整方案拆成可连续验收的跨页面工作包。每个工作包完成后都要有可运行代码、对应测试和浏览器演示脚本；局部按钮或字段只有在所属工作包的闭环明确后才实现。

## 总体顺序

| 优先级 | 工作包 | 依赖 | 当前状态 | 完成证据 |
|---|---|---|---|---|
| P0 | 六域信息架构与统一布局 | 现有路由 | 本提交完成导航分组和角色菜单守卫 | `navigation.test.mjs`、前端构建 |
| P0 | 单一真实 API 通道 | P0 导航 | 已完成：认证、集合、总览和业务写入统一走 Server；已移除浏览器 mock、演示种子和 `VITE_DATA_MODE` | Server-only 源码契约、前端构建、真实靶机回归 |
| P0 | 通用状态与表格组件 | P0 布局/API | 已完成：共享加载、错误、空状态和 `DataTable` 默认空态已覆盖资产、扫描、漏洞、报告、系统和总览列表 | `DataState.test.mjs`、21 项前端测试、前端构建 |
| P1 | 资产 → 扫描 → 结果核心旅程 | P0 | 已有真实 SQLite/Worker 闭环，缺 Playwright 5 点击验收 | 隔离实验环境 E2E、授权范围抓包证据 |
| P1 | 漏洞处置与总览下钻 | P0 | 服务端和页面能力已实现，缺真实浏览器回归 | 数字与明细一致、URL 筛选回归 |
| P1 | 报告、定时与系统管理 | P0 | 主体已实现；系统设置、独立通知中心、PDF 尚缺 | API/权限/审计和浏览器验收 |
| P2 | 真实引擎与平台适配 | P0/P1 | 实验靶机链路已具备，真实服务器、国产系统和 PostgreSQL 尚待验收 | 隔离靶机测试、引擎日志、范围抓包 |
| P2 | 性能、无障碍、国际化 | 所有 P1 | 未完成 | 1 万条列表、键盘操作、i18n 检查 |

## 本轮推进边界

本轮已完成 P0 的信息架构基础和真实数据通道收敛：一级导航固定为“总览、资产、扫描、漏洞、报告、系统”六个域，子入口只引用已有真实路由；未实现的系统设置和通知中心不提前显示。这样后续的通用组件、真实 API 和种子数据会有稳定的页面归属，不再继续向平铺导航追加零散入口。

下一步按依赖顺序补三条核心旅程的浏览器验收，再处理报告 PDF、通知中心和系统设置等领域闭环。系统设置、通知中心和报告 PDF 会在其领域闭环准备好后加入系统域。

## 交付约束

- 真实扫描仍只接受已登记且明确授权的数字 IP 和端口；路线图不扩大扫描范围。
- 真实测试只使用隔离靶机和明确授权的目标；不能把本地扫描结果或密钥写入仓库。
- 每个工作包完成时同步 `docs/product/current-state.md`、`docs/verification-log.md` 和相应 OpenAPI 契约。
