> 配套文档:`docs/architecture-v3.2.md`(架构依据)、`AGENTS.md`(代码规则)。
> 本计划用于**每天核对 Codex 的实际进度**。日期按工作日计数,节假日自动顺延。
> 当前为待人工确认的计划文档。PR #1 的拆分与关闭以 `docs/codex-task-split-pr1.md` 为准;本文件不代表代码已完成验收,也不豁免其中的执行门禁。

## 0. 使用说明

### 0.1 前提假设

- 1 名人工负责人(评审、拍板、实验环境),Codex 负责编码。**进度瓶颈通常是人工评审,不是编码**。
- 采用**服务器版优先**路线,便携版在 MVP 末期先搭"嵌入式单进程"骨架(Day 48–49),完整便携版放到 Phase 2。
- 工期是目标值。Phase 0 结束后用实际速度重新估算后续周期。

### 0.2 推进规则

1. **每天一个 PR(或一个明确的提交集合)**,PR 描述里附验收命令和输出摘要。
2. **当天验收不通过,不进入下一天的新任务**,先用缓冲日修复。
3. **每周最后一天为"周门禁"**:当周所有验收通过、安全关键模块已人工评审合并,才进入下一周。
4. 标记"**重点**"的任务,涉及 `AGENTS.md` 第 8.3 节列出的模块,必须人工逐行评审后合并。
5. Codex 不得声称"已验证"而实际没有运行;未验证的部分必须在汇报里明确列出。

### 0.3 状态标记

| 标记 | 含义 |
|---|---|
| ⬜ | 未开始 |
| 🔄 | 进行中 |
| ✅ | 验收通过并已合并 |
| 🟡 | 部分完成(注明缺口) |
| ❌ | 验收未通过 |

### 0.4 每日汇报模板(要求 Codex 每个任务结束时按此填写)

```markdown
## Day N 汇报
- 任务:
- PR / 提交:
- 完成项:
- 未完成项及原因:
- 验证证据(命令 + 输出摘要):
  - make build:
  - make lint:
  - make test(含 -race):
  - 本任务验收命令:
- 未能验证的内容:
- 涉及的 AGENTS.md 硬规则条目:
- 需要人工重点评审的位置(文件:行号):
- 偏离计划之处:
- 需要人工决策的问题:
- 明日计划:
```

### 0.5 你每天只需要核对这 5 件事

1. PR 是否存在、CI 是否全绿。
2. 汇报里的"验证证据"是否和你自己在本地跑出来的一致(抽查 `make test`)。
3. "未能验证的内容"是否合理、有没有被悄悄略过。
4. 是否触碰了不属于当天任务的文件(看 diff 文件列表)。
5. 重点任务是否已排上人工评审。

## 7. PR A 评审清单(Day 1 使用,由原 PR #1 拆出)

本清单与 `docs/codex-task-split-pr1.md` 的 11 个评审问题一并核对,不能替代逐条结论与文件:行号。

**租约**
- [ ] 本地到期判断使用单调时钟,不受系统时间调整影响;`hard_deadline` 基于墙上时间的部分有单独说明。
- [ ] Worker 的本地"失联自终止"阈值**小于** Server 的租约时长并留出时钟偏差余量,避免 Server 已重新分配任务而原 Worker 仍在跑。
- [ ] "终止未确认"之后会强制杀掉整个进程树(含子进程),且不得对 Server 声称租约已释放。
- [ ] 续约失败不延长租期;续约成功才刷新。

**GC**
- [ ] 无法向 Server 确认时一律拒绝回收(失败即关闭)。
- [ ] 两个阶段都向 Server 按**本节点**查询;多 Worker 共用一个目录时能正确合并。
- [ ] Server 端拒绝把新租约绑定到已退役版本。
- [ ] 版本号按数值比较,而不是字符串字典序。
- [ ] 宽限期下限(不少于 2 小时)无法被配置绕过。

**测试**
- [ ] 使用可注入的假时钟做确定性测试。
- [ ] 覆盖 Server 超时、部分响应、进程被强杀等异常路径。
- [ ] `-race` 重复运行稳定。
